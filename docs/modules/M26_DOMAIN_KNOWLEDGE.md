## One-liner

For ADA, **“knowing” a life-admin domain** means **organ knowledge** (schemas, units, resolve rules, tools in packs) plus optional **reference knowledge** (cited domain docs for briefs/campaigns) — **never** invented nutrients, sole-pick `ref_id`, or a nutrition essay in the cortex prompt.

---

## Core research question

For a personal agent on this Pi, what does **“knowing”** food / gym / time / habits / people mean in **engineering terms** — without soul or omniscience — such that capture gets smarter, resolve/recover/teach-in improve, and later brief/analysis can use **honest logs**, **without** replacing Verb→Pack, Confirm, or code-bound ids?

**Operator vision (encode, don’t fanfiction):** humans are signal-driven organisms; food = energy/nutrients; gym = load/adaptation; time = finite capacity; habits = compounding; people = social graph. ADA should understand **what capture is for**, not pretend lived consciousness.

## Three kinds of “know”

### 1. Organ know (schemas · units · tools · resolve rules)

**Definition:** Everything the **pack spine + gateway tools** need to turn NL into **honest, typed writes** without guessing facts.

| Lives in | Examples (food · gym · time · habits · people) |
|----------|--------------------------------------------------|
| Pack YAML + spine code | `meal_log` lines[]; `lift_log` sets[]; `time_start` kind; habit `routine_run`; people alias resolve |
| Tool schemas (`toolspec`) | `life_meal_log`, `life_lift_log`, `life_food_search`, … |
| SQLite / FACTS shapes | Nutrient snapshot columns; `exercise_catalog`; timer row; habit streak row; `people` aliases |
| Resolve rules (deterministic) | FDC detail before insert; null-CORE drop; favorite → local → USDA; gym fold/alias; brand_fight → Confirm |
| Unit normalization | g/ml/serving; kg/reps/RPE; minutes; date-local “today” |

**EVIDENCE:** Personal informatics systems separate **collection** (capture) from **integration/reflection** ([Li et al., stage model, CHI 2010](https://doi.org/10.1145/1753326.1753611)). ADA maps **collection** to organ know + logs; **reflection** to later P4 reads — not prompt weights.

**Cortex role:** propose **slot labels** inside fence (e.g. line list, exercise name string) — **never** sole authority on ids, macros, or “what you ate.”

### 2. Reference know (cited domain docs in memory)

**Definition:** **Stable, citable prose** (operator + evidence) that explains **what the domain is for** and how to read logs — for **briefs, campaigns, teach-in explanations**, and operator research. Not a substitute for FDC rows or gym catalog ids.

| Lives in | Shape | Used when |
|----------|-------|-----------|
| `memory/domain/<domain>.md` (proposed) or WORLDVIEW with cite-ids | Sections with `cite:` / FACT pointers; versioned | Morning brief section; “why protein matters” explain; campaign digest |
| M10 library cites | External papers, USDA docs | Research pack; optional grounding for reference doc authoring |
| FACTS | Operator targets, split, aliases | Teach-in sticky truth |

**EVIDENCE:** Agent memory surveys: **semantic memory** for interpretive layer must **cite** episodic/structured stores ([Zhang et al. 2024](https://arxiv.org/abs/2404.13501); [Anatomy of Agentic Memory, 2026](https://arxiv.org/html/2602.19320)). Reference know = interpretive; logs = episodic truth.

**Distinction — research-for-operator vs search-tool-at-runtime:**

| Mode | Who | When | Egress |
|------|-----|------|--------|
| **Research-for-operator** | Cursor/implement chat writes/updates domain card + reference doc | Phase 0–2 design | Operator session |
| **Search-tool-at-runtime** | `web_fetch` / `web_cite_search` inside **campaign or brief pack** | Explicit watch/brief — not daily `meal_log` | M07 allowlist + caps |

Daily capture **does not** web-hunt papers. Recover **does not** read reference doc for kcal.

### 3. Reject (do not call this “knowing”)

| Reject | Why |
|--------|-----|
| Prompt nutrition / gym physiology essay in charter | Unbounded, unverifiable, invents when FDC null (**METAL:** egg null-CORE) |
| Cortex sole-pick `ref_id` / exercise_id | Violates M21/M24/M25; Consent Integrity |
| Invent macros / load / duration when tool miss | Truth > charm; M25 falsifier F-M25-1 |
| Consciousness / “I feel your hunger” | Constitution §4–7 |
| RAG-only brain replacing meal rows | Structured logs > RAG-brain (`00` §3.3) |
| Mid-meal unbounded ReAct | Horizon gap; daily log must stay capped ([Horizon Gap, 2026](https://arxiv.org/html/2608.06663)) |

## Domain-agnostic capture grammar

Shared shape for **every** life-admin vertical. Verbs name the pack; ontology names **slots and resolve doors**.

```text
utterance
  → pack_router (Verb→Pack)
  → decompose? (M24 when N slots)
  → slot fill (cortex assist INSIDE fence)
  → resolve chain (favorite → local → remote catalog → alias table)
  → bind decision (code: unique | ambiguous | miss | empty_payload)
  → Confirm? (ingress; gateway args)
  → tool write → receipt
  → episodic log row(s)
  → optional sticky FACT (M22 teach-in)
```

| Stage | Verbs help | Ontology (organ know) helps |
|-------|------------|----------------------------|
| Route | `meal_log` vs `lift_log` vs `time_start` | Pack hint; chip aliases; **vocative filler** (`Hi Ada.`) stripped before name scrape — later lock, food OPEN #4 |
| Decompose | — | Meal lines; lift sets; due objects |
| Resolve | — | Units, catalogs, alias tables, null rules |
| Bind | — | `decide_food_bind`, exercise fold, person alias |
| Recover | — | Alt queries, detail refresh (M25) — **organ**, not reference |
| Write | Tool name in receipt | Schema validation, honest_partial |
| Remember | `food_preset_save`, favorites | FACT keys — operator truth |

**ReAct alignment ([Yao et al. 2022](https://arxiv.org/abs/2210.03629)):** interleave **tool observations** (search results, catalog rows) with next step — **inside the pack**, capped. Not freestyle tool loop across domains.

**Personal informatics alignment ([Choe et al., quantified-self practices, CHI 2014](https://doi.org/10.1145/2556284.2556964)):** low-friction **collection** first; reflection/analysis **later** on accumulated honest data — maps to P0 capture → P4 analysis.
